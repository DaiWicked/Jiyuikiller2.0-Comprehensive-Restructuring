## 6. 剩余两项的技术方案（恢复时直接照做）

### (a) 超椭圆圆角（squircle）
- 现状：`NavBarClipRoot.Clip` 用 `RectangleGeometry` + `RadiusX/Y=23`（正圆角）。窗体圆角同理（`GlassClipRoot`，半径 15）。
- 参考：`工程文件2\colorui\coui-squircle\src\commonMain\kotlin\io\github\suqi8\coui\kmp\squircle\SquirclePath.kt`（超椭圆路径算法）
- WPF 做法：把 `Clip` 从 `RectangleGeometry` 换成 `PathGeometry`，用三次贝塞尔近似 iOS 的连续性圆角（`k≈0.42~0.55` 的平滑因子），由 C# 按当前尺寸重建几何。
- 风险/成本：**中高**。它影响的不只是底栏——窗体主圆角、`NavBarFrame`、渐变描边都要同步，否则内外圆角不匹配会出现"黑角"（历史上踩过）。建议先用一个独立分支只改底栏验证观感。

### (b) 指示器玻璃化（nested glass）
- 现状：`NavIndicator` 是一个带渐变背景 + 描边的圆角矩形，只做 X 平移动画（`AnimateNavIndicator`）。
- 参考：`liquid-glass-js-main` 的 "Nested Glass System"（子元素采样父容器输出）。
- WPF 做法：给 `NavIndicator` 加一个 `VisualBrush` 采样 `NavBarClipRoot`（或直接复用 `NavBarGlassBrush` 但把 Viewbox 缩放到指示器矩形），再叠一个轻量折射/高光；配合原来的 X 平移动画。
- 风险/成本：**中**。要小心 `VisualBrush` 采样祖先造成循环引用（WPF 会取上一帧，通常可接受但会有一帧延迟）。

## 7. 踩过的坑（改这块代码前务必读，能省大量时间）

| 坑 | 事实 |
|---|---|
| **`Application.Resources` 会自动冻结 Freezable** | 把画刷写进 `Application.Resources` 会被 WPF `SealIfSealable` 冻住，`BeginAnimation` 必抛"已密封或已冻结"。普通 `ResourceDictionary` 不会。⇒ 冻结的画刷要 `Clone()` 后**只作元素本地值，不要塞回字典**。（源码依据：`ResourceDictionary.cs` 里 `_ownerApps != null` 分支） |
| `ScaleTransform.CenterX/CenterY` 单位是**像素** | 写 `0.5` 不是"居中"而是"离左边 0.5px"。要用 `RenderTransformOrigin="0.5,0.5"`。 |
| `ClipToBounds` **只裁矩形** | `Border.CornerRadius` 不裁子元素。圆角必须用 `Border.Clip` 的 `RectangleGeometry`，或祖先容器上挂圆角 `Clip`。 |
| **`RenderTargetBitmap` 会执行 ShaderEffect** | 已实测（红色 shader 把蓝底变红）。所以可以用它做效果自检。 |
| `PixelShader` 的 pack URI 不解析时构造期不抛 | 构造期 `IsShaderLoaded` 区分不出"资源缺失"。真正失败发生在渲染期。 |
| **改 `.hlsl` 必须重编 `.ps`** | 否则改动完全无效（很容易忘记）。 |
| 自检代码自身的坑（我踩过两次） | ① 设完 `Strength` 又调 `UpdateNavBarLensParams()`，它会按设置覆盖回去 ⇒ A/B 变同一种渲染；② 渲染图已被 Clip，**x=0 就是玻璃左边缘**，按"元素坐标"取窗口会落到折射带之外。 |
| 驱动源码是 GBK | 用 `[System.Text.Encoding]::GetEncoding(936)` 读；源码在 `C:\Users\Administrator\Desktop\工程文件\JiYuKiller\JiYuTrainerDriver\`（**不在本项目里**，项目只带编译好的 `.sys`）。 |
